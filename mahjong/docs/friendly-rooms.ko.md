# 단판전·반장전과 AI 친선전

## 혼자 서버 대국 시험하기

1. 앱 상단에서 H룰 또는 S룰과 **단판전 / 반장전**을 선택한다.
2. 플레이 모드를 **친구와 4인 대국**으로 바꾼다.
3. 이름을 입력하고 **방 만들기**를 누른다.
4. **빈자리를 AI로 채우고 시작**을 누른다. 사람 1명과 AI 3명이 무작위 자리에 앉는다.

친구가 먼저 입장하면 사람 2명+AI 2명, 사람 3명+AI 1명으로도 시작할 수 있다. 이 버튼은 방장에게만 보인다. 사람 4명이 모이면 기존처럼 자동 시작한다. 시작 후 자리를 사람으로 교체하는 기능은 없다. AI의 성향은 빈자리 순으로 균형형 E·최속 A·고득점 D다. S룰에서는 별도의 S 정책을 사용한다.

## 대국 형식

혼자 연습과 4인 친선전 모두 다음 조합을 선택할 수 있다. 버튼은 **다음 새 대국·새 방**에 적용한다. 이미 시작한 국이나 들어간 방의 형식은 중간에 바뀌지 않으며, 초대받은 사람은 방장이 만든 방의 룰·형식을 따른다.

|룰|단판전|반장전|
|---|---|---|
|H|배패부터 세 번째 화료 또는 유국까지 한 국|동1~남4 진행. 첫 화료 사건에 친이 포함될 때만 연장. 첫 사건에 친이 없거나 화료 없는 유국이면 교대|
|S|첫 화료 기회의 복수 론 또는 쯔모, 유국으로 한 국 종료. 친 화료·텐파이에도 종료|동1~남4 진행. 친 화료·텐파이는 연장하므로 8국보다 많을 수 있음|

현행 H 규칙 `H-2026-jp-20261014` 반장전은 **첫 화료 사건에 친이 포함될 때만 연장**한다. 첫 쯔모·론이 친의 화료이거나 첫 화료를 일으킨 버림패의 동시 복수 론에 친이 포함되면 연장한다. 타가가 먼저 화료한 뒤 친이 별도의 두 번째·세 번째 화료를 하면 교대한다. 화료 없이 유국되면 친이 텐파이여도 교대하며, 먼저 화료한 사람이 있다면 첫 사건 기준을 따른다.

이전 앱은 친이 어느 순서로든 화료하면 연장했다. 사용자 제보를 확인하고 위 기준으로 정정했다. 일본어 안내 §8.2.3은 PK 화료 순번을 명시하지 않으므로, 이번 정정은 **앱 운영 기준이며 공식 재정이 확인됐다는 뜻이 아니다.** 동남전 전체 구성·남4 종료도 앱의 보충 운영 방식이다. [개정 안내 대조](rulebook-update-20261015.ko.md)에 원문과 해석을 구분했다.

새 S 규칙은 `S-2026-jp-20261014`다. 구 H `H-2026-private-kan-v1` 등으로 저장된 반장·방은 당시 설정대로 친 연장 없이 8국을 진행한다. 현행 H의 이번 연장 판정 수정은 저장된 솔로·친선전에도 적용한다. 진행 중인 국은 종료 시 새 기준으로 판정하고, 다음 국 시작 대기 중이면 아직 시작하지 않은 연장·교대 예정만 바로잡는다. 이미 다음 국을 시작했으면 그 국을 되돌리지 않는다. 지난 점수·완료 기록·구 H 대국은 보존한다.

H는 0점에서 시작하는 누적 순수익을 표시하고, S는 25,000점부터 시작한다. S 단판도 종료 시 남은 공탁은 1위에게 지급하며, 동점은 시작 동·남·서·북 순서로 처리한다. 이는 앱의 종료 공탁 처리 가정이다.

반장에서는 처음 플레이어 배치를 유지한 채 현재 자풍만 친에 따라 회전한다. 매 국의 점수를 한 번만 누적하고 남4국 종료까지 점수표를 저장한다. H에서 먼저 화료해도 남은 AI는 해당 국의 세 번째 화료 또는 유국까지 계속 진행한다. 새로고침하면 같은 탭의 자기 자리로 돌아온다. 방은 생성 후 6시간 유지된다. 혼자 연습은 이 브라우저의 저장된 대국 이어하기로 복원할 수 있고, 단판·반장 점수표는 JSON/CSV로 내려받을 수 있다.

AI 판단은 서버의 로컬 코드로 실행하며 LLM/API를 호출하지 않는다. 상대의 비공개 손패나 패산을 정책에 전달하지 않는다. 새 행동은 약 0.7초 뒤 허용되며 화면의 상태 조회 주기만큼 더 늦게 보일 수 있다. 사람이 행동하거나 상태를 조회할 때 진행하므로 모든 사람이 창을 닫으면 AI만 계속 돌지 않는다.

## 개발 환경에서 시험하기

서로 다른 터미널에서 실행한다.

```bash
npm run serve
npm run serve:rooms
```

브라우저에서 `http://127.0.0.1:8787`을 열고 위 순서로 진행한다. 방 API는 `http://127.0.0.1:8790`이며 개발용 DB는 `.local/rooms.sqlite`에 저장된다. 사람 4명 동작은 별도 브라우저 프로필이나 독립 창에서 방 코드로 입장해 확인한다. 로그인 키를 공유하는 탭 복제 대신 독립 세션을 사용한다.

서버 회귀 검증:

```bash
node --test test/server-ai.test.mjs test/multiplayer.test.mjs test/s-room.test.mjs test/match-formats.test.mjs test/h-match-rulebook-20261014.test.mjs
```

검증 항목은 방장 권한, 중복 시작, 마지막 사람 입장과 AI 시작 경합, 숨겨진 패 비공개, 0.7초 전 무진행, 동시 상태 조회의 중복 행동 방지, 사람/AI 복수 론과 후로 우선순위, H 첫 화료 사건의 친 포함 여부·동시 복수 론·남4 종료, S 반장 완주다. H 테스트는 같은 초기 상태에서 직접 실행한 순차 엔진과 서버 최종 상태도 비교한다. 과거 H의 8국 고정 방식은 당시 규칙을 지정한 별도 회귀 검사로 유지한다.
